# 5. Безопасность, надёжность и качество

[К оглавлению HLD](../customer-support-agent-hld.md) · [Состояние](02-state-lifecycle.md) · [12 принципов](04-12-principles.md)

## 5.1. Границы доверия

- Браузер, сообщения, FAQ и найденные документы — входные данные. Инструкции внутри них не могут менять политику, права или условия согласия.
- Клиент и организация определяются сервером. Проверка доступа обязательна для истории, источников, событий, операций и обращения к оператору. Гость не получает прошлые обращения аккаунта до разрешённой привязки.
- Ключи LLM и бизнес-систем находятся только на сервере. В контекст передаются минимально необходимые данные без секретов.
- Предпочтителен API на origin сайта. Сессионные cookies используют `Secure`, `HttpOnly` и подходящий `SameSite`; изменяющие состояние запросы защищены от CSRF, origin проверяется. Для другого origin отдельно определяются CORS, авторизация и ограничения встраивания.
- Ответы и ссылки безопасно обрабатываются перед отображением. Платёжные данные, содержимое форм и секреты из URL не копируются в чат автоматически.
- Истечение или отзыв сессии прекращает доступ к SSE; при каждой подписке / переподключении права проверяются заново. Выход из аккаунта очищает отображаемые персональные данные.
- Полные персональные данные не дублируются в технических логах. Сроки хранения, удаление, размещение и передача данных провайдеру LLM определяются перед реализацией.

## 5.2. Обработка ошибок и ограничения

Нормализованная ошибка содержит `tool`, `code`, безопасное описание, статус операции (`not_started / failed / unknown`), признак допустимости повтора и `correlation_id`. Полный технический стек остаётся в защищённых логах. Модель получает достаточно информации для выбора разрешённого следующего шага; её решение всё равно проверяет сервер.

| Ситуация | Поведение |
| --- | --- |
| Недостаточно источников | Уточнение / оператор; факты не выдумываются |
| Недоступен LLM / поиск | Ограниченный повтор при допустимости, затем понятный статус и доступный путь к оператору |
| Некорректный структурированный выход | Не исполнять; ограниченная коррекция либо безопасное завершение |
| Истёкшее / изменённое предложение | Отклонить; при необходимости создать новое предложение и запросить новое согласие |
| Неизвестен результат бизнес-API | Сверить статус; не повторять потенциально выполненную операцию вслепую |
| Достигнут лимит шагов / времени / стоимости | Сохранить причину, сообщить клиенту, передать оператору по политике |
| Недоступна операторская очередь | Показать статус; повторить создание той же заявки безопасно либо предложить доступный альтернативный процесс |

Лимиты числа шагов, повторов, задержки, стоимости и срока ожиданий задаются конфигурацией и фиксируются для AgentRun. Конкретные значения ещё не определены.

## 5.3. Наблюдаемость

Трасса связывает `conversation_id → run_id → step_id → action_id / handoff_id → execution_id`. Сохраняются версии промпта, модели, контрактов и источников, причины решений о переходах, события согласия и проверенные результаты. Приватные рассуждения модели для аудита не требуются.

Метрики: время первого ответа и полного решения, качество поиска и подтверждённость ответов источниками, доля решённых обращений, причины передач, ожидание оператора, успешность операций, длительность `unknown`, лаг outbox, повторы, стоимость и число шагов. Показатели дополняются оценкой фактической удовлетворённости клиента; уменьшение передач само по себе не доказывает качество.

## 5.4. Проверки до запуска и при изменении поведения

| Область | Проверяемый результат |
| --- | --- |
| Знания и контекст | Релевантный FAQ, корректные ссылки, актуальная версия, недостаток данных, длинная история, неверное резюме |
| Доступ | Изоляция клиентов / организаций, гостевой режим, отсутствие чужой истории при смене аккаунта |
| Промпты и контракты | Регрессии на типовых обращениях, неизвестный инструмент, некорректные аргументы, инструкции в документах |
| Согласие | Отказ, истечение, изменение параметров, чужой `action_id`, двойной клик и гонка подтверждения с отменой |
| Исполнение | Тайм-аут до / после внешнего эффекта, дубли outbox, сверка неизвестного результата, отсутствие ложного успеха |
| Владение | Одновременное принятие операторами, старый ответ бота, позднее принятие заявки, уже исполняемая операция при передаче |
| Восстановление | Переход страницы, перезагрузка, несколько вкладок, разрыв SSE, пропущенные / повторные события, перезапуск обработчика |
| Ограничения | Предсказуемая остановка по бюджету, отсутствие бесконечного цикла, понятное уведомление |

Набор оценок включает эталонные случаи и обезличенные проблемные обращения. Изменения промптов, контекстной сборки, моделей, инструментов и поиска проверяются совместно. Перед выпуском задаются измеримые критерии приёмки; значений SLA и порогов в этой концептуальной HLD пока нет.
